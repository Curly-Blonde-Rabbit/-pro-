# 单硬盘与 A B 回退

## 存储层次

可见主硬盘使用一个 ext4 文件系统。业务数据目录位于其中；两个 3 GiB 的系统镜像也位于同一文件系统内，不向用户显示成两个磁盘。

机内保底 Linux 使用独立区域，普通 A/B 系统镜像损坏时仍可接管。它不等同于 B 系统镜像，也不随普通业务数据清理一起格式化。

本机线性映射的顺序是主区域、原 system_a 区域、原 vendor_a 区域、原 vendor_b 区域，追加部分共 5 GiB。没有移动保底 Linux，也没有为本轮合并修改 GPT。

## 完整性约束

映射器读取设备自己的私有安装计划，核对 GPT 双副本校验、分区标签和 UUID、起点、长度、内核设备号、文件系统 UUID、映射表和读写模式。它不是按设备号盲目拼接。

正式启用后拒绝把较短的原始主分区当成整个文件系统直接挂载。映射失败应进入独立保底系统，不尝试用旧的短分区作为业务盘继续启动。

`dlt_main_pool.py` 仅管理受限的内核映射，不负责格式化或扩容。初次迁移中的扩容由独立维护步骤执行；常规启动不运行 resize2fs。

设备容量、分区 UUID、Wi-Fi 和维护身份不是通用常量，不能把别人的安装计划复制到另一台手机上执行。

## 容量显示

原始映射容量、文件系统块容量、statfs 可用总容量和剩余可用容量是不同指标。文件系统元数据不计入界面的可用总容量。GiB 使用 2 的 30 次方字节，GB 使用十进制；不要混用。

本机追加原始容量为 5,368,709,120 字节，验收时剩余可用容量增加 5,284,495,360 字节。界面最终只显示一个“硬盘”项。
